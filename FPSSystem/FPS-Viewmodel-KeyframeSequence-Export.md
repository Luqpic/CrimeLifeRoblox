# Viewmodel animations exported as linear KeyframeSequences

Status: Built and verified live in `FPS System.rbxl` (Edit mode). The sequences exist in
`ServerStorage.ViewmodelKeyframeSequences` and are **not yet published** — publishing needs a
person, because asset upload is not available through the Studio MCP server. Nothing in the
runtime path was changed by this export; the game still runs on the procedural motion module.

## Summary

Follow-up to `FPS-Viewmodel-Animation-Linear-Easing.md`. The authored viewmodel joint motion is
now also available as 49 editable `KeyframeSequence` objects — 410 keyframes, 2,047 poses, 26
keyframe markers — so the animation set can be refactored in the Animation Editor instead of by
editing pose tables in Luau. Every pose is `Enum.PoseEasingStyle.Linear`.

Generated by `FPSSystem/ViewmodelAnimations/ExportKeyframeSequences.luau`, which is re-runnable:
it rebuilds the whole output folder from whatever `WeaponViewmodelMotion` currently holds.

## Scope: viewmodel rig only

The brief was explicit that this must be the viewmodel animations, not the player animations.
The export reads only `ReplicatedStorage.Blaster.ViewModels.*`, whose rigs are
`Root -> Body -> {Magazine, RightArm, ChargingHandle}` with `LeftArm` parented under `Magazine`
on magazine-fed weapons and under `Body` on melee and shotguns. These rigs carry an
`AnimationController` and `Animator` and have no `Humanoid`; they are a separate hierarchy from
the character rig that `CharacterAnimationController` drives.

Verified rather than asserted: across all 2,047 exported poses the only part names present are
`Root`, `Body`, `Magazine`, `LeftArm`, `RightArm`, `ChargingHandle`. Character-rig parts found: none.

Class representatives were deliberately chosen from outside the module's `showcase` table, so a
class folder holds the generic class track. AK47, Glock 17 and Mossberg 590 are exported
separately by name because their carry pose and reload phrasing are authored per weapon and a
class-only export would silently drop them.

Clip durations are read from the weapon Tool attributes (`reloadTime`, `swingDelay`), not
hardcoded, so exported lengths match gameplay. Shotgun reload clips are per-shell (0.45s / 0.50s),
matching how those weapons actually reload.

`KeyframeMarker` instances are emitted at the module's sound marker times — `MagOut`, `MagIn`,
`Charger` — so `bindSoundsToAnimationEvents` keeps working if the asset path is restored.

## Verification

- **Faithfulness.** The exported keys were linearly interpolated at times deliberately chosen to
  fall *between* keyframes and compared against the live module's joint output at the same time.
  Worst error across AK47 Reload, rifle Reload, melee Shoot2 and pump Equip: **0.00028 studs**.
  This confirms both that the export is correct and that linear keys are sufficient — no easing
  curve is needed to reproduce the current motion.
- **Easing.** 2,047 / 2,047 poses are `Linear`, all at `Weight = 1`.
- **Melee contact.** The `melee.Shoot` keyframe times are 0.0000, 0.1100, **0.2000**, 0.2658,
  0.4700. The contact key lands exactly on `swingDelay` = 0.2. The three swing variants have
  distinct contact poses: Shoot (-0.060, -0.120, -0.430), Shoot2 (-0.320, 0.020, -0.340),
  Shoot3 (0.160, -0.060, -0.390).
- **Carry poses.** Only AK47 (0.6874), Glock 17 (0.6073) and Mossberg 590 (0.5040) have a
  non-identity Idle Body offset; the nine class Idles are 0.0000 as expected.

## Notes

**Idle clips are intentionally a rest pose.** Idle breathing, walk bob, sprint lean and the ADS
offset are not joint motion — `WeaponViewmodelMotion:step` returns them as a single pivot offset
that `ViewModelController` applies via `model:PivotTo`. They cannot be baked into a joint
animation, and should not be: pivot-level sway is the correct place for viewmodel bob. An
asset-based refactor therefore replaces equip / shoot / reload only, and the sway stays procedural.

**Firearm Shoot is resampled, not keyed.** Recoil is a critically damped spring rather than an
authored track, so it is integrated at 60 Hz and keyed at 30 Hz over its decay window. It is the
one clip whose keyframes are samples rather than authored intent, and the one most worth
re-authoring by hand.

**The melee `Reload` slot stays dead.** `Motion:reload` early-returns on `kind == "melee"` and
both melee tools carry `reloadTime = 0`, so no melee Reload clip was exported.

To take these live: publish each `KeyframeSequence` (right-click in Explorer, Save to Roblox),
paste the returned ids into the matching `Animation` objects in each viewmodel's `Animations`
folder, then restore the two controllers in `FPSSystem/ViewmodelAnimations/baseline/`, which is
the asset-driven playback path. Until that is done the export is inert and gameplay is unchanged.
