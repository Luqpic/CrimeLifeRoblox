# Ask First Then Build

## Rule

1. Research enough to ask good questions, then ask **all** the questions needed up front, in one round of `AskUserQuestion` pickers (several back to back when there are more than 4).
2. Then build to the end **without stopping to ask again**. Decide the rest yourself and record each call as a ruling in the batch note.
3. Ask only when the choice is genuinely the developer's: content, feel, asset ids, prices, damage and other numbers they care about. Recommended option first, short labels, detail in each option's description.
4. Never ask with a numbered text list.
5. Do not re-ask a question the developer already answered: check `80 Decisions` first ([[Decisions MOC]]).
6. If a test needs something only the developer can do (a device emulator toggle, a multiplayer Start, a look at the screen), ask for it in the same picker round.
7. When several readings of a request exist, present them instead of picking silently; push back when something simpler exists.

## Why

Carried from the developer's OBT rules (same developer): on 2026-09-30 they said the picker is easier to read and answer than a wall of text, and on 2026-10-09 asked to be asked everything first and then have the work run to the end. Adopted for CrimeLife on 2026-11-14 with this vault. No CrimeLife-specific quote is recorded.

## How to apply

- First step of a batch: read [[Open Items]] and the touched systems, then one picker round ([[Batch Workflow]] step 1).
- Record every picker answer in its `80 Decisions` note.
